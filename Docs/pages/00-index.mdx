# aweXpect.Chronology

[aweXpect.Chronology](https://github.com/Testably/aweXpect.Chronology) contains extension methods that create `TimeSpan`, `DateTime`, `DateTimeOffset`, `DateOnly` and `TimeOnly` values that read like the sentence you would say, e.g. `5.Seconds()` or `24.December(2024)`. Tests no longer need to spell out constructor arguments in the right order, so their dates and durations are easy to read and hard to get wrong. It belongs to the [aweXpect](/aweXpect) family, but does not depend on aweXpect, so you can use it in any code.

## Installation

<PackageInstall package="aweXpect.Chronology" />

The extension methods are in the `aweXpect.Chronology` namespace:

```csharp
using aweXpect.Chronology;
```

:::info[Target frameworks]
The package supports .NET Standard 2.0, .NET 8 and .NET 10. The `DateOnly` and `TimeOnly` conversions require .NET 8 or later.
:::

The methods return lightweight builders that convert implicitly to the .NET types, so you can pass them wherever a `TimeSpan`, `DateTime` or `DateTimeOffset` is expected, e.g. in an [aweXpect](/aweXpect) expectation:

```csharp
TimeSpan duration = 42.Seconds();

await That(duration).IsEqualTo(43.Seconds()).Within(1.Seconds());
```

`ToString()` returns the value as text, so string interpolation and the debugger show e.g. `00:05:00` for `5.Minutes()`.

## TimeSpan

### Units

The package adds the extension methods `Ticks()`, `Microseconds()`, `Milliseconds()`, `Seconds()`, `Minutes()`, `Hours()`, `Days()` and `Weeks()` on `int` and `double` (`Ticks()` on `int` and `long`):

```csharp
TimeSpan timeout = 10.Seconds();
TimeSpan duration = 1.5.Hours();
TimeSpan retention = 2.Weeks();
TimeSpan latency = 250.Microseconds();
```

### Combine values

Each method has an overload that adds another `TimeSpan`, so you can write a value with several units:

```csharp
TimeSpan timeout = 1.Minutes(30.Seconds()); // 00:01:30
TimeSpan period = 2.Days(12.Hours());       // 2.12:00:00
```

### Arithmetic

The result supports the operators `+`, `-`, `*` (by `double`, in either order), `/` (by `double`) and unary negation:

```csharp
TimeSpan doubled = 5.Minutes() * 2;
TimeSpan tripled = 3 * 5.Minutes();
TimeSpan half = 5.Minutes() / 2;
TimeSpan combined = 1.Minutes() + 30.Seconds();
TimeSpan negative = -10.Seconds();
```

### Comparison

Two durations can be compared with `==`, `!=`, `<`, `<=`, `>` and `>=`:

```csharp
bool isLonger = 5.Minutes() > 30.Seconds(); // true
```

## Dates and times

### Dates

The package adds an extension method on `int` for each month, which takes the day and the year:

```csharp
DateTime christmasEve = 24.December(2024);
```

:::note
The date has the time 00:00 and the `DateTimeKind` `Unspecified`. Set the [kind](#kind) explicitly when the value is compared with UTC or local times.
:::

### Time of day

`At` sets the time of day, either with explicit components or with a `TimeSpan`:

```csharp
DateTime time = 24.December(2024).At(18, 30);
DateTime preciseTime = 24.December(2024).At(18, 30, 45, 500);
DateTime fromTimeSpan = 24.December(2024).At(18.Hours(30.Minutes()));
```

`At` also works on an existing `DateTime` or `DateOnly` and replaces its time of day.

A component outside its range, e.g. `At(24, 0)` or `At(18, 60)`, and a `TimeSpan` outside a single day, e.g. `At(24.Hours())` or `At(-1.Hours())`, throw an `ArgumentOutOfRangeException`.

### Kind

`AsUtc()` and `AsLocal()` set the `DateTimeKind` of a date with a time of day or of an existing `DateTime`:

```csharp
DateTime utc = 24.December(2024).At(18, 30).AsUtc();
DateTime local = 24.December(2024).At(18, 30).AsLocal();
```

:::tip
A date without a time has no `AsUtc()` or `AsLocal()`. Add the time explicitly, e.g. `24.December(2024).At(0, 0).AsUtc()` for midnight UTC.
:::

`ToLocalTime()` and `ToUniversalTime()` convert a date with a time of day to the local time zone or to UTC, like the `DateTime` methods with the same name. Use them when the system under test converts the value the same way:

```csharp
DateTime expected = 1.January(1601).At(0, 0).AsUtc().ToLocalTime();
```

:::warning
`AsUtc()` and `AsLocal()` keep the clock time and only set the kind, while `ToLocalTime()` and `ToUniversalTime()` change the clock time, so the result depends on the time zone of the machine. Set the kind first: like `DateTime`, `ToLocalTime()` treats an `Unspecified` value as UTC and `ToUniversalTime()` treats it as local time.
:::

### Relative dates

`Before` and `After` on a `TimeSpan` express a date relative to another one:

```csharp
DateTime earlier = 3.Hours().Before(25.December(2024));
DateTime later = 3.Hours().After(25.December(2024));
```

With a `DateTimeOffset`, the result keeps its offset:

```csharp
DateTimeOffset earlier = 3.Hours().Before(25.December(2024).At(12, 0).WithOffset(2.Hours())); // 09:00 +02:00
```

### Add and subtract

You can add a `TimeSpan` to a date or subtract one from it:

```csharp
DateTime evening = 24.December(2024) + 18.Hours();
DateTime dayBefore = 24.December(2024) - 1.Days();
```

### Compare dates

Two dates, or two dates with a time of day, can be compared with `==`, `!=`, `<`, `<=`, `>` and `>=`. Like `DateTime`, the comparison ignores the kind:

```csharp
bool isEarlier = 24.December(2024) < 25.December(2024); // true
```

## DateTimeOffset

`WithOffset` attaches a UTC offset to a date, a date with a time of day or an existing `DateTime`:

```csharp
DateTimeOffset date = 24.December(2024).WithOffset(1.Hours());
DateTimeOffset time = 24.December(2024).At(14, 30).WithOffset(2.Hours());
```

:::warning
For a `DateTime` with the kind `Utc` or `Local`, the offset has to match: `24.December(2024).At(14, 30).AsUtc().WithOffset(2.Hours())` throws an `ArgumentException`. Use an `Unspecified` value, as in the examples above, or the matching offset.
:::

The result also supports `+` and `-` with a `TimeSpan`, and `==`, `!=`, `<`, `<=`, `>` and `>=` with another result. Like `DateTimeOffset`, the comparison uses the point in time, so `24.December(2024).At(14, 30).WithOffset(2.Hours()) == 24.December(2024).At(12, 30).WithOffset(0.Hours())` is `true`. When you assign it to a `DateTime`, it keeps the clock time and drops the offset.

## DateOnly and TimeOnly

:::info[.NET 8 or later]
The conversions to `DateOnly` and `TimeOnly` are only available on .NET 8 and later.
:::

The results convert implicitly to `DateOnly` and `TimeOnly`:

```csharp
DateOnly date = 24.December(2024);
TimeOnly time = 18.Hours(30.Minutes());
TimeOnly timeOfDay = 24.December(2024).At(18, 30);
```

A date converts to `DateOnly`, a duration to `TimeOnly`, and a date with a time of day or an offset to both.
